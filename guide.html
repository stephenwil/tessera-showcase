Tessera

A Wee book about a voxel fantasy console for the browser: what it is, how a frame gets made, what a cart looks like inside, and how to write your first one.

A tessera is one tile of a mosaic. In Tessera every voxel is a tile. This edition describes the high-res console as it is built: a 256 × 256 × 128 world drawn at 768 × 432. For the deep dive into each part, read Tessera High-Res, explained.

The puppy-island beach, painted once at load into a 480 × 270 canvas and scaled up with chunky pixels, in the spirit of Tessera's own 768 × 432 picture. Its colours come from the guide's first draft palette. This is an illustration, not the real renderer.

01What Tessera is

Tessera is a general-purpose fantasy console: a pretend games machine with fixed, small limits that lives in a web page. Instead of a flat screen of pixels it has a box of 3D voxels, and you program it in Lua. The limits are the point. A fixed world, 255 colours and four sound channels keep carts quick to make and easy to share.

The first cart is a port of Puppy Coast: Hat Chase, the three.js game, and it plays at 60 fps on a desktop GPU and on a phone. Chapter 9 shows how that game maps onto Tessera piece by piece.

02A box of tiles

The whole display is one block of voxels, 256 wide, 256 deep and 128 tall. Tessera puts z up, so x and y are positions on the ground (x east, y north) and z is height. Each voxel holds one byte: 0 means empty, and 1 to 255 pick a colour from the palette.

The palette

Each cart can define its own 255 colours. A cart that defines none gets the default Tessera palette, laid out as a 16 × 16 grid so you can find colours by row and column.

03One frame

Tessera keeps two layers. The map layer is the world that stays put: terrain, buildings, the lighthouse. You build it once in _init. The draw layer is everything that moves: characters, the sea, sparkles. It lives in its own layer, which cls() empties at the start of every frame, and is redrawn on top of the map.

Timing

A cart has three functions. _init runs once when the cart loads. _update runs exactly 30 times a second and should hold the game rules. _draw runs once for every frame the screen shows and should only draw.

04Making the picture

Tessera does not turn voxels into triangles. A WebGL2 fragment shader shoots one ray per pixel of a fixed 768 × 432 picture into the two 3D textures and walks it voxel by voxel with a DDA (a digital differential analyser: step to whichever cell edge is nearer, x or y or z, and check that cell). The camera is orthographic, so every ray points the same way, about 35° down, just like the Hat Chase camera today. The small picture is then scaled up with nearest-neighbour sampling, which gives the chunky look.

Shading, in four cheap steps

  • Face light: top, side and front faces get fixed brightness levels, so shapes read clearly.
  • Sun shadow: one extra ray toward the sun, as in Figure 7.
  • Ambient occlusion: peek at a few neighbouring voxels and darken corners a little.
  • Fog (optional): fade distant voxels toward a colour set by fog(c, density).
  • Frame reuse: when nothing changed since the last frame, the renderer shows the last picture again instead of raymarching.

On top sits a 768 × 432 2D overlay for HUD text and icons in a built-in 5 × 7 pixel font. The overlay is drawn after the raymarch, so text is always crisp and never hidden behind voxels.

Built to be swapped

The core sits behind a "machine level" boundary. Only plain data crosses it: cart text in, button states in, and out come the two 8 MiB layers, the palette, camera numbers, HUD commands and sound events. Nothing on the outside knows which language the core is written in.

In code, the boundary is small enough to write on one card:

// The machine boundary: the object createCore() returns (src/core/core.js).
// A later Rust core fills the same ports.
const core = await createCore();

core.load(cartText);   // fresh machine, parse, run the Lua: {ok} or {ok: false, error}
core.init();           // runs _init once
core.tick();           // one 30 Hz tick: runs _update
core.draw();           // runs _draw into the draw layer

core.input;      // Float32Array(33): 4 players x (6 buttons + 2 axes), then mute
core.map;        // Uint8Array, 256*256*128 = 8,388,608 bytes
core.drawLayer;  // Uint8Array, same size, emptied by cls()
core.palette;    // Uint8Array(768): 256 x RGB
core.view;       // Float32Array(16): camera, zoom, yaw, sun, sky, fog
core.overlay;    // HUD commands for this frame
core.sounds;     // sfx / tone events since the shell last took them
core.storage;    // dset / dget values
core.error;      // {line, message} for the Tessera error screen, or null

In a later Rust version, the layers would be views straight into WebAssembly memory, so nothing is copied before upload.

06Carts

A cart is everything a game needs in one file: its name, colours, voxel models, sounds and code. It comes in two forms that hold the same thing.

07The API

Every function a cart can call, grouped by job (src/core/api.js). Square brackets mark optional arguments. Coordinates are voxels (x, y across, z up) for the 3D calls and pixels for the HUD. Buttons: 0 left, 1 right, 2 up, 3 down, 4 A (Z or Space), 5 B (X or E), and the same on a standard gamepad.

08Your first cart

Six steps from an empty cart to a hat you can steer, with sound and a save. Each step adds a little to the last. The pictures are sketches of what you should see; paste a step into the code editor (F4) to see the real thing.

  1. Step 1Hello, box

    Every cart is Lua 5.4. Tessera calls _draw once per displayed frame. Clear, draw one box, print one line.

    function _draw()
  cls()                                 -- empty the draw layer
  box(120,120,0, 135,135,15, 76)        -- a 16-voxel sand cube
  print("hello, tessera", 8, 8, 15)     -- HUD text, white
end

    You should see: A sand-coloured cube in the middle of the floor, and white pixel text in the top-left corner.

  2. Step 2Make it bounce

    t() is the time in seconds. Lua has no +=, and maths lives in math.

    function _draw()
  cls()
  local z = 16 + math.abs(math.sin(t() * 3)) * 80
  sphere(128,128,z, 16, 23)                -- radius 16, red
  print("boing", 8, 8, 15)
end

    You should see: A red ball bouncing up and down about once a second. Nothing needs erasing: cls() empties the draw layer every frame.

  3. Step 3Build a world once

    Things that never move go on the map layer in _init. It stays put; cls() only empties the draw layer on top of it.

    function _init()
  mbox(0,196,0, 255,255,0, 168)      -- sea to the north (high y)
  mbox(0,0,0,   255,195,1, 76)       -- sand, 2 voxels deep
  for x = 226,243 do                 -- one striped hut
    local c = (x // 2 % 2 == 0) and 23 or 15
    mbox(x,140,2, x,159,24, c)
  end
end

function _draw()
  cls()                              -- the map stays
end

    You should see: A beach: a strip of sea at the back, sand everywhere else, and one red-and-white striped hut.

  4. Step 4Move the hat

    Read buttons in _update (30 times a second) and draw in _draw. Buttons 0–3 are left, right, up, down; up is north, which is +y.

    hx, hy = 128, 96

function _update()
  if btn(0) then hx = hx - 2 end
  if btn(1) then hx = hx + 2 end
  if btn(2) then hy = hy + 2 end     -- up = north = +y
  if btn(3) then hy = hy - 2 end
end

function _draw()
  cls()
  model("hat", hx, hy, mheight(hx, hy))
  camera(hx, hy, 0)                  -- follow the hat
end

    You should see: The red hat sits on the sand. Arrow keys or WASD (or a drag on a touch screen) slide it around and the camera follows. (Add your _init from step 3 and a hat model in the cart's __models__.)

  5. Step 5Make a sound

    btnp is true only on the tick a button goes down. tone plays a quick pitch slide.

    function _update()
  -- ... movement from step 4 ...
  if btnp(4) then                    -- A: Z or Space
    tone("square", 880, 440, 0.15, 0.5)
  end
  if btnp(5) then sfx(0) end         -- B: sound 0 from __sfx__
end

    You should see: Press Z or Space for a short falling “boop”. X or E plays sound 0 from the cart. M mutes.

  6. Step 6Save your cart

    Open the pause menu to export a .tess.png picture cart with a screenshot on the front, or keep the .tess text file. Drag either one onto Tessera to load it, or open ?cart= with a bundled cart's name.

    -- high scores survive between plays:
function _init()
  best = dget(0)                     -- save slot 0
end
function win(score)
  if score > best then best = score; dset(0, best) end
end

    You should see: Two files: hat.tess (readable text, good for git) and hat.tess.png (a picture you can share). Both load the same cart.

09Porting Hat Chase

Hat Chase already had the Tessera shape: a 128 × 128 beach, voxel models made of coloured cubes, an orthographic camera and small synth sounds. The port moved each part to the matching Tessera feature, then doubled everything for the high-res world. The cart's source lives in the private tessera-hatchase repo; this repo keeps the built carts/hatchase.tess.

10Built and next

Built

  • Name Tessera; carts .tess and .tess.png (export from the pause menu, drag-drop to load)
  • 256 × 256 × 128 volume, 1 byte per voxel, map and draw layers of 8 MiB each
  • Per-cart palette of 255 colours, 0 empty, default palette as fallback
  • WebGL2 orthographic DDA raymarcher at 768 × 432, brick uploads, frame reuse, plus a 5 × 7 font overlay
  • Fixed 30 Hz _update; _draw every displayed frame
  • Lua 5.4 via wasmoon, with a watchdog and cart line numbers on errors
  • Keyboard, gamepad (menus too) and touch; 4-channel synth; mute
  • Code editor (F4) with Lua colouring and jump-to-error; stats overlay (F3)
  • Hat Chase, 60 fps on a desktop GPU and a phone, plus more carts in carts/

Next

  • Voxel model editor: needs its own spec first
  • Faster raymarching if a heavier cart needs it: brick skipping, half-res rays, fewer shadow rays
  • Host-side collision probes, so carts make fewer Lua-to-host calls
  • Music: a __music__ section and a pattern player
  • Rust core with Lua in the same .wasm: when a benchmark says it is worth it
  • Still open: model() rotation at odd angles fattens thin models; touch needs a real-tablet check
